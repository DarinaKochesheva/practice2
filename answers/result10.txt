Вопрос 1
Что выведет этот код? Объясните порядок выполнения блоков.

java
class Demo {
    static { System.out.print("A "); }
    { System.out.print("B "); }
    Demo() { System.out.print("C "); }
    public static void main(String[] args) {
        System.out.print("D ");
        new Demo();
        System.out.print("E ");
        new Demo();
    }
}

Предсказанный вывод:
A D B C E B C

Объяснение:
A — статический блок
D — первая инструкция main
B — блок инициализации (перед конструктором)
C — конструктор
E — вторая инструкция main
B — блок инициализации для второго объекта
C — конструктор для второго объекта




Вопрос 2
Класс `Child` в пакете `b`, класс `Parent` в пакете `a`. `Child extends Parent`. Какие члены `Parent` доступны в `Child`? А какие доступны в другом классе пакета `b`, который НЕ наследует `Parent`?

ответ:
В классе Child (наследник из другого пакета) доступны public и protected члены родителя. В другом классе того же пакета b, который не наследует Parent, доступны только public члены. private и package-private недоступны ни там, ни там.




Вопрос 3
Можно ли создать sealed-класс, у которого все наследники — record? Какое преимущество это даёт при использовании в switch?

ответ:
Да, можно. Преимущество в switch в том, что можно использовать паттерн-матчинг record — распаковывать поля прямо в case, а sealed гарантирует, что компилятор проверит обработку всех возможных типов.




Вопрос 4
Что выведет этот код? Объясните, что такое String Pool и как работает `intern()`.

java
String a = "Hello";
String b = new String("Hello");
String c = b.intern();
System.out.println(a == b);
System.out.println(a == c);
System.out.println(b == c);

Предсказанный вывод:
false
true
false

Объяснение:
a — литерал, хранится в String Pool. b создан через new — это отдельный объект в куче. c получен через intern() — возвращает ссылку из пула, те тот же объект, что и a. Поэтому a и b — разные объекты, a и c — один объект, b и c — разные.




Вопрос 5
Почему этот код не компилируется? Как исправить?

java
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }
class C implements A, B { }

ответ:
Код не компилируется из-за конфликта имён — оба интерфейса имеют одинаковый default-метод hello(), и компилятор не знает, какой выбрать. Исправить можно, переопределив метод в классе C и указав через super, какой интерфейс использовать.




Вопрос 6
В чём разница между `StringBuilder` и `StringBuffer`? Приведите конкретный сценарий, когда нужен именно `StringBuffer`.

ответ:
StringBuilder не потокобезопасен и быстрее, StringBuffer потокобезопасен и медленнее. StringBuffer нужен, когда одну строку изменяют несколько потоков одновременно, например, общий лог-буфер в многопоточном приложении.




Вопрос 7
Что выведет этот код? Объясните, что происходит с переменной `x` в лямбде.

java
int x = 10;
Runnable r = () -> System.out.println(x);
// x = 20;  // что будет, если раскомментировать?
r.run();

Предсказанный вывод:
10

Объяснение:
Лямбда может использовать только effectively final переменные — те, которые не меняются после инициализации. Если раскомментировать строку x = 20, код не скомпилируется, т.к переменная перестанет быть effectively final.




Вопрос 8
Напишите пример лямбда-выражения, которое нельзя заменить на ссылку на метод. Объясните почему.

пример и объяснение:
Predicate<String> isLong = s -> s.length() > 5;

Эту лямбду нельзя заменить на ссылку на метод, потому что она не просто вызывает один метод, а выполняет операцию сравнения результата с числом. Ссылки на методы работают только для случаев прямого вызова метода без дополнительных операций.




Вопрос 9
Чем `EnumMap` быстрее `HashMap` для ключей-enum? Опишите внутреннюю реализацию в одном предложении.

ответ:
EnumMap внутри хранит значения в обычном массиве, где индекс элемента — это порядковый номер enum-константы. Это позволяет получать доступ за O(1) без вычисления хэш-кода, что намного быстрее, чем HashMap.




Вопрос 10
Дан `record Point(int x, int y) {}`. Что сгенерирует компилятор автоматически? Можно ли добавить в record изменяемое поле? Можно ли наследоваться от record?

ответ:
Компилятор автоматически генерирует конструктор со всеми полями, геттеры с именами как у полей (без приставки get), методы equals, hashCode и toString. Добавить изменяемое поле в record нельзя — все поля final. Наследоваться от record тоже нельзя, так как record неявно является final-классом.
